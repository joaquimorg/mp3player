# T-Watch MP3: App Windows, envio por USB e indicação de progresso — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add on-watch transfer progress, a serial command/upload protocol and `twatch.local` to the firmware, plus a Windows Forms app (`TWatchMP3.exe`) that configures Wi-Fi over USB, manages the 4 slots and sends music (YouTube or file) by Wi-Fi when configured, otherwise by serial.

**Architecture:** Firmware gets a shared `transfer` progress state used by HTTP and serial uploads, a pure-logic `serproto` library (command parsing, CRC, block framing) and a serial task in the release firmware. The app is plain C# compiled with the `csc.exe` shipped in Windows; its decisions live in a pure `AppLogic` class tested by a console test runner.

**Tech Stack:** Existing firmware (PlatformIO, Arduino-ESP32 2.0.x, Unity tests on device via `pio test -e watch_test`), ESPmDNS (core), C# / Windows Forms / System.IO.Ports (.NET Framework 4.x `csc.exe`), yt-dlp.exe, ffmpeg.exe.

**Specs:** `docs/superpowers/specs/2026-11-03-pc-app-design.md` (binding) and `docs/superpowers/specs/2026-11-02-watch-mp3-player-design.md`. Context: the earlier plan `docs/superpowers/plans/2026-11-02-watch-mp3-player.md` is complete; its ledger lives in `.superpowers/sdd/`.

## Global Constraints

- All files under `D:\Work\TTGO-Watch\mp3player`. Watch on `COM8`. The PC has other USB-serial devices (COM1, COM15, COM18, COM19): the app and any test script must never send anything but `TWATCH?\n` to a port it has not identified, and must skip busy ports.
- Wi-Fi and Bluetooth are never on together (existing state machine). Serial commands never bypass it: mode changes go through the existing host request path.
- Never wipe NVS; NEVER run `watch_test_destructive`. The watch has Wi-Fi credentials and the paired earbuds saved; Wi-Fi password must never be echoed, logged, written to files, reports or commits.
- Serial: 115200 baud default, lines end `\n`, replies `OK ...` or `ERRO <motivo>`; `WIFI <ssid>\t<palavra-passe>` (TAB-separated); ssid 1-32 bytes, password empty or 8-63 bytes; line limit 200 bytes (`ERRO tamanho`).
- Serial upload: `PUT <slot> <tamanho> <crc32 hex> <nome UTF-8 em hex>` then blocks `<seq 1 byte><dados ≤4096><crc16 CCITT of seq+dados, 2 bytes>`; replies `K`/`R` per block; client retries a block up to 5 times, 3 s reply timeout; watch aborts after 5 s without data; final `OK <crc32>`; commit only through `storage::SlotWriter::commit()`; `BAUD 921600` allowed, watch returns to 115200 at the end or on failure. Space rule: `tamanho + 16384 <= storage::freeBytes()` (`slotlogic::validateUpload`).
- Upload size limit: only free space; app refuses a converted result above 12 MB. Encode 44.1 kHz at 112 kbps; if it doesn't fit, retry 64 kbps mono.
- mDNS name `twatch.local` (HTTP port 80) in Programação mode only.
- All UI text and messages in Portuguese (Portugal). App: Windows Forms, 3 tabs (Relógio, Músicas, Ferramentas), `.exe` built by `app\compilar.bat` with `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`, no SDK/Python/installer.
- The default `watch` firmware must contain no debug-only code; test hooks only under `UI_DEBUG` or in dev scripts.

## Review Focus

1. USB cable pulled / app killed / window closed mid serial-upload → after 5 s the tmp file is removed, the previous slot is intact, playback resumes, serial returns to 115200.
2. Garbage or boot-log bytes on the serial line, a half line, a 10 KB line without newline, binary junk between commands → `ERRO` or ignored, no crash, no stuck state; app probing COM15/18/19 (other devices) must not disturb them.
3. Wi-Fi password with spaces, quotes, `&`, non-ASCII, a TAB-less line, too short/long → rejected with a clear `ERRO` or stored exactly; never echoed in any reply or log (including the app's log window).
4. Mode change or `PUT` requested while an upload (HTTP or serial) is running or while a mode switch is already in progress → `ERRO ocupado`, no deadlock, no half-written slot.
5. Duplicate block after a lost `K`, corrupted block (bad CRC16), wrong total CRC32, size that lies (fewer/more bytes than announced) → resend/abort cleanly; slot unchanged on failure.

### Task 2: Serial protocol library (pure)

**Files:** Create `lib/serproto/serproto.h`, `lib/serproto/serproto.cpp`, `test/test_serproto/test_serproto.cpp`; Modify `platformio.ini` (test filters if needed; native test_filter lists `test_serproto`).

**Interfaces (namespace `serproto`, no Arduino includes):**
- `enum class Cmd { Unknown, Hello, Wifi, WifiCheck, ModeProg, ModePlay, Baud, Put, Cancel, List };` (`WifiCheck` = `WIFI? <ssid>\t<pass>`, validate-only dry run used by tests; `List` = `LISTA`, parsed here, implemented in Task 8)
- `struct Parsed { Cmd cmd; char ssid[33]; char pass[64]; int slot; uint32_t size; uint32_t crc32; char name[49]; int baud; const char* err; };`
- `bool parseLine(const char* line, size_t len, Parsed& out)` — returns false with `out.err` ("comando","tamanho","argumentos","wifi") on failure. `TWATCH?`; `WIFI <ssid>\t<pass>` (ssid 1-32, pass 0 or 8-63, bytes); `MODO PROG|PLAY`; `BAUD 921600|115200`; `PUT <slot 1-4> <size> <crc32 hex 8> <name hex>` (name ≤48 bytes decoded, valid hex, UTF-8 bytes accepted verbatim); `CANCELAR`. Lines >200 bytes → "tamanho".
- `uint16_t crc16ccitt(const uint8_t*, size_t, uint16_t init=0xFFFF)`; `uint32_t crc32Update(uint32_t crc, const uint8_t*, size_t)` / `crc32Final`; `bool hexDecode(const char*, uint8_t* out, size_t cap, size_t& n)`.
- `class BlockReceiver`: `BlockReceiver(uint32_t total)`; `enum class Result { NeedMore, Ok, OkDuplicate, BadCrc, BadSeq, Done }`; `Result feed(const uint8_t* b, size_t n, size_t& consumed)` assembling `[seq][data][crc16]` with expected `len = min(4096, remaining)`; exposes `const uint8_t* data()`, `size_t dataLen()`, `uint32_t received()`, `uint32_t crc32()`; a repeated previous `seq` with good CRC → `OkDuplicate` (not counted again); wrong seq → `BadSeq`.

- [ ] **Step 1: Failing tests:** `crc16ccitt("123456789",9)==0x29B1`; `crc32` of "123456789" == 0xCBF43926; parse cases: `TWATCH?`→Hello; `WIFI casa\tabc12345`→ssid "casa"; `WIFI minha rede\tcom espacos 1` (spaces both fields) OK; `WIFI x\t1234567` (7-char pass) → err "wifi"; empty pass OK; no TAB → err "argumentos"; 33-byte ssid → err; password with `&"é` stored exactly; `PUT 1 1000 DEADBEEF 616263` ok with name "abc"; `PUT 5 ...` err; 201-byte line → "tamanho"; `MODO PROG`; `BAUD 9600` → err; garbage `\xFF\x00xx` → Unknown/err with no crash; BlockReceiver: two blocks (4096 + 904) assembles and ends Done with right crc32; bad crc16 → BadCrc; duplicate seq → OkDuplicate; wrong seq → BadSeq; a block split across 3 `feed` calls works.

### Task 4: Serial upload (PUT) state machine

**Files:** Modify `src/seriallink.cpp/.h`; Create `tools/pc/serial-put.ps1` (dev harness); Test `test/test_serproto` (+ `BlockReceiver` already covered).

**Interfaces:** Consumes `serproto::BlockReceiver`, `storage::SlotWriter`, `slotlogic::validateUpload` (first 4 bytes of block 0, `size`, `storage::freeBytes()`), `transfer::*` (`Source::Usb`), `player::pause()/resume()` (resume only if it was playing), `storage::setSlotName` after commit.
- `PUT` → validates everything possible before accepting (slot, size, space; MP3 head is checked when block 0 arrives → `R`-less abort with `ERRO nao-mp3`), replies `OK PUT`. Then block loop with `K`/`R`; 5 s without data → `abort()`; `CANCELAR` → abort + `OK`; at the end verify total crc32, `commit()`, `setSlotName`, reply `OK <crc32>`. `BAUD 921600` switches `Serial.updateBaudRate` after replying `OK` and returns to 115200 on end/failure/timeout. While a PUT is active other commands except `CANCELAR` return `ERRO ocupado`. Playback resumes after success or failure; free heap flat.

- [ ] **Step 1:** implement. **Step 2:** `tools/pc/serial-put.ps1 -Port COM8 -File x.mp3 -Slot 1 [-Baud 921600] [-Name nome]` implementing the client side (blocks, retries, timing) for tests only.
- [ ] **Step 3: Verify:** 1 MB and 4.4 MB uploads at 115200 and 921600 (report throughput), the slot plays/is listed by `GET /api/slots` afterwards (enter Programação), non-MP3 refused, size larger than free refused immediately, a corrupted block (script option `-CorruptBlock 3`) is retried and succeeds, a duplicated block (script option `-DropAck 2`) doesn't double-write (final crc matches), killing the script mid-transfer → after ≥5 s `TWATCH?` works at 115200 and the old slot is intact and no `.tmp` remains, `Failed` banner shown, playback resumed.
